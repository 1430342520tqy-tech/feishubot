## 一、目标与硬性要求

**目标**：全自动加密合约跟单机器人 —— 自动盯飞书群 KOL 信号（**文字 + K线图**），
解析出「币种/方向/入场/加仓/止损/多档止盈」，在**币安 USDT-M 永续**下单并动态管理。

**硬性要求**：
1. 先 dryRun（纸面）跑通，用户点头才碰真钱
2. 数据必须真实可核验，**禁止编造**
3. 每一单都要看得懂（币种/开单时间/入场/止损/止盈/结单结果），**做成表格**
4. **只做 USDT 结尾的币种**（`XAUUSD` 是图表写法，币安上是 `XAUUSDT`）
5. 读图必须 100% 正确
6. **四档止盈只按三档做，第四档无视**
7. 信号可能是 1~3 条消息（文案/卡片/图）任意组合，必须合并
8. 通知含：币种/时间/金额/杠杆/止损位/止损点数(不含杠杆)/各档止盈/各档预期收益率（**含3倍杠杆**）
9. 博主发止盈通报时，回报用户自己的持仓
10. 代码更新及时上传 GitHub

## 三、交易执行规范（核心）

### 资金参数
| 项 | 值 |
|---|---|
| 单笔保证金 | **300 USDT** |
| 杠杆 | **3 倍** |
| 单笔名义 | 900 USDT |
| 最大同时持仓 | **5 笔** |
| 止盈档位 | **3 档**（第4档无视） |
| 测试模式 | 忽略 5 笔上限（仅测试期） |
| 轮询 | 0.5 秒 |
| 待合并窗口 | **4 秒** |

### 开仓价规则
比较博主点位与当前市价，差值 = (市价 − 博主价) / 博主价：

| 情形 | 动作 |
|---|---|
| 差值 **≤ 2%** | 直接市价、一次满仓 900U |
| **做多**且市价高于博主价 **>2%** | **不追高**：博主价×1.01 挂 150U + 博主价 挂 150U |
| **做空**且市价低于博主价 **>2%** | **不追空**：博主价×0.99 挂 150U + 博主价 挂 150U |
| 做多时市价低于博主价 / 做空时市价高于博主价 | 直接市价，止损不变 |

> 两笔各 150U 是**保证金**（×3 = 各 450U 名义，合计 900U 名义）。

### 区间信号
入场价 = 区间中点 `(A+B)/2`，小数部分**向上取整到该合约 tickSize**。

### 止损止盈
- **开仓全用市价**，**只有止盈止损用限价挂单**
- 止盈每档平 **1/3**
- **TP1 成交后止损立刻移到开仓价（保本损）**
- 止损/止盈**优先用 K 线图上读到的**（博主按图交易）

### 读图规则（必须 100% 正确）
- **红色横线 / 暗红区间 = 止损位**（在开仓价**下面**）
- **开仓价 = 止损上方第一个价格标签**
- **止盈 = 开仓价上方的实线横线**（不限颜色），只取前 3 档，第 4 档忽略
- 判定"是不是止盈线"用**横线像素覆盖率**：实线 ≈ 0.85~1.0；价格轴数字/当前价虚线/开仓标记 < 0.6

### 绝对底线
- **止损和止盈都没读到 → 只发「待确认」，绝不下单、绝不猜**
- 一切数值必须来自真实接口 / 真实图片

### 用户已明确不需要的
- **美股代币休市时不设禁止开单窗口** —— 休市时博主开仓照常跟进（已实测：休市盘口活跃、
  开盘跳空最大仅 0.034%，相对 2~5% 的止损距离可忽略）

## 九、停机丢信号：机制与修复（2026-09-13）

### 问题机制
旧代码在 `main()` 启动、每开完一个群页面时执行：

```python
last_id[g] = max(last_id.get(g, 0), max(ids))   # 把游标直接抬到"页面最新一条"
```

游标 `last_id` 是"上次处理到哪条"。这一行让游标从**上次停机前的位置**跳到**当前最新**，
中间那段消息 ID 全部小于新游标 → **永远不被当作新消息 → 静默丢弃，连日志都不留一行。**

### 实测数据（服务器 run.log）
最近一次重启（10:02:56 旧进程最后心跳 → 10:03:00 新进程启动 → 10:07:20 才开始实时监控）：

| 群 | 游标跳前 | 跳后 | 该群盲窗 |
|---|---|---|---|
| 机器人开单通知 | 09-13 01:24 | 09-13 01:24:16 | 57 秒 |
| 暴富龙 | 09-11 21:02 | 09-11 21:02:50 | 105 秒 |
| UA-nurseneil2 | 09-12 23:40 | 09-12 23:40:20 | 180 秒 |
| 颜驰2群 | 09-11 21:01 | 09-11 21:01:05 | 215 秒 |
| 黄金mansoor | 09-12 02:23 | 09-12 02:23:07 | **260 秒** |

> 那次重启实际只吞掉几秒~几十秒的窗口（这几个群当时确实安静）。
> **机制是结构性的：一旦重启窗口内有信号，必丢且无告警。** 该进程已重启 29 次。

### 附带发现
- **`>15 条静默全丢`**：旧代码 `if len(new) > 15: new = []`，一次发现超过 15 条就整批丢弃。
  与重启无关，群里刷屏 >15 条即触发。日志里尚未出现过，属潜伏隐患。
- **页面永久失联**：旧代码 `if page is None: continue`，页面重开失败一次 → 该群**永久停止监控且无提示**。
- 开页脆弱：`标题不符` 累计 **110 次**，是 4.5 分钟开页耗时的主要来源。

### 已实施的修复（方案A + 方案B）
**方案A —— 游标续读 + 回补闸门**
- `adopt_page()`：开页时**不再抬游标**；无历史游标的新群才用"页面最新"初始化。
- 首扫自然回补 `id > 游标` 的积压消息，按时间升序处理。
- **时效闸门** `CATCHUP_MAX_AGE = 1800`（30 分钟）：更老的开单信号**只通报、不下单**，避免拿过期点位追单。
- **数量上限** `CATCHUP_MAX_MSGS = 50`：一次最多真处理 50 条，其余只通报。
- 被拦下的消息**推进游标 + 标记已处理**（永不重复），并汇总推一条
  `【跟单机器人】⚠️ 回补闸门拦下 N 条消息` 给你 —— **不再静默**。
- **逐条推进游标**：进程中途挂掉时只会**重放**（`SEEN` 挡住重复开单），不会丢单。

**方案B —— 配置热加载**
- 主循环检测 `runtime_config.json` 的 mtime，变了就热加载，**不重启进程** → 常见重启场景盲窗归零。
- 移除的群自动关页面释放内存；新增的群只新开 1 个页面（约 1 分钟）。
- `修改监控群 / 修改金额 / 修改杠杆 / 测试模式` 指令现在**立即生效，不需要重启**。

### 残余限制（必须知道）
DOM 只渲染最近若干条消息。**停机久到超出页面可见范围的信号仍然读不回** ——
所以核心原则不变：**尽量别频繁重启；要改配置用指令热加载，不要手动 restart。**

| 撤单 | `DELETE /fapi/v1/algoOrder`，必填 `algoId` 或 `clientAlgoId` |
| 查挂单 | `GET /fapi/v1/openAlgoOrders` |
| **`reduceOnly`** | **会被拒**：`-1106 Parameter 'reduceonly' sent when not required`（双向持仓下本就不该传） |
| `algoType` 合法值 | `CONDITIONAL`（另有非法值返回 `-4500 Invalid algoType`） |
| `closePosition=true` | 支持，但走 GTE 语义，**要求已有持仓**，无仓返回 `-4509` |
| **没有 `/test` 版本** | `POST /fapi/v1/algoOrder/test` → **404** |

> 因为 Algo 接口没有 test 端点，自检改用 **`quantity="0"`** 做参数校验：
> 若返回 `-4003 Quantity less than or equal to zero` 说明**其余参数全部被接受**，
> 且数量为 0 保证不可能成交。这是无持仓情况下唯一安全的验证方式。

### 为什么止损不能用限价单
做多时止损价在市价**下方**。若挂 `SELL LIMIT` 在该价，币安规则是「市价 ≥ 限价即可成交」，
而当前市价本来就更高 → **会立刻以市价成交，等于一开仓就平仓**。
所以止损必须是触发单 `STOP_MARKET`。**止盈可以用限价单**（挂在目标价，吃 maker 万2）。

### 双向持仓模式
按用户 2026-09-13 的决定：同一币种可能同时持多与持空（用户选的博主覆盖山寨/主流/黄金/美股四类）。
所有订单带 `positionSide`（LONG/SHORT），**不传 `reduceOnly`**（已实测被拒）。平仓方向：
平多 = `SELL` + `positionSide=LONG`；平空 = `BUY` + `positionSide=SHORT`。
