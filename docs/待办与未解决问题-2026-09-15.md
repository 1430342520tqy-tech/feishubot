## 一、已确认的 bug / 缺口

### B1 —— 浏览器上下文死亡后无法自愈（最高优先级）

**真实事故证据**
```
16:00:26  🎛 收到指令：持仓情况            ← 最后一次正常
16:07:40  页面不存在/已关闭，正在重新打开…
16:07:51  页面不存在/已关闭，正在重新打开…   ← 每 3 秒重试，一直失败
17:19:17  重开失败：BrowserContext.new_page: Target page, context or browser has been closed
   ⋯ 心跳一直打「运行中 | 持仓 6 笔」       ← 看起来正常，实际完全读不到任何群
17:40:15  重启机器人 → 恢复
```

**后果**：机器人"瞎"了 **93 分钟**，期间四个群的消息**全部漏掉**；
用户 16:37 发的「只开btc和doge」、17:10 发的「持仓情况」「帮助」**根本没被读到** →
用户感知为"机器人指令没反应"。

**根因**：整个 `BrowserContext` 死亡。上一轮加的"页面重开失败继续重试"
**只覆盖标签页被关，覆盖不了上下文整体死亡** —— `ctx.new_page()` 必然失败。

**修法**：检测到 `Target page, context or browser has been closed`
→ **主动重启整个浏览器**（重新 `launch_persistent_context` + 重开所有页面 + 重新预热），并**立即告警**。

**旁证**：内核日志**无 OOM 记录**，不是内存问题，更像 Chromium 自身崩溃。

### B2 —— 失联看门狗阈值太长 + 检测维度不够

- 现状 `silence_alert_hours: 6` → **6 小时才报警，救不了 B1 这种 93 分钟的事故**
- 需：① 阈值收紧（建议 30 分钟，可配）② **检测"页面连续打不开 N 次"→ 立即告警**

**✅ 已发现低成本捷径**：`tools/health_check.py` 第 4 项**本来就会扫日志里的「失败/错误」行**，
实测能把 `BrowserContext.new_page: ... has been closed` 原样列出（32 条）。
→ 加 **cron / systemd timer，每 5 分钟跑一次 health_check**，
命中 `BrowserContext` / `页面不存在` / `重开失败` 或输出含「发现 N 个问题」→ **立刻推飞书告警**。
**不依赖机器人进程活着**，能同时兜住 B1 与 B2，改动极小，建议优先做。

### B3 —— 多币种分支绕过了合理性校验

`split_by_coin` → 直接 `ask_user`，**没经过 `finalize_pending` 那套校验**
（止损方向、价格合理性、点数换算）。

**证据**：DOGE 做多，入场 0.079、**止损 0.09（高于入场价）** ——
按已有校验**本该被拒绝**，但因走多币种分支直接发给用户审批了。

**修法**：把校验抽成公共函数，两条路径都过。

### B4 —— 多币种审批选项不完整

### B5 —— 解析体系对"点数 / 条件单 / 语序"无能为力

**原始消息 → 实际解析（错误）对照**
```
原文：以太坊空单…在2465跌破可以追空，止损带个30点左右，止盈就30点以上分批止盈。
      比特币等待76000跌破收回，站稳76200多，74000止损，可以设置条件单…2000点以上的止盈利润。
      狗狗币在0.078到0.08接多，左侧轻仓，0.075止损，止盈0.09附近。

实际：ETH  做空 开仓=2465.0 止损=30.0  止盈=[30.0, 2465.0]   ← 完全错误
      BTC  做多 开仓=76200.0 止损=74000.0 止盈=未读到        ← 条件单，不该直接开
      DOGE 做多 开仓=0.079 止损=0.09 止盈=[0.09]            ← 止损错（0.09 是止盈）
```

| 子问题 | 说明 | 正确结果 |
|---|---|---|
| **点数 vs 价格** | 「止损带个30点左右」「止盈就30点以上」的 **30 是点数** | ETH 入场 2465 → 止损 **2495**、止盈 **2435** |
| **数字在关键词前** | 「0.075止损」现有正则要求 `止损` 在数字前，故漏读 | DOGE 止损 **0.075** |
| **条件单** | 「等待76000跌破收回，站稳76200多」「跌破2465可以追空」= 条件触发才进 | **必须送审批，不得自动开** |
| **止损止盈互混** | DOGE 把止盈 0.09 当成止损 | 必须交叉校验 |

## 三、相关设计原则（改代码时必须遵守）

1. **绝不猜价** —— 读不准就询问用户，不自动开单
2. **绝不静默丢弃** —— 任何解析失败/未识别信号都要留日志并通知
3. **默认不碰真钱** —— `binance_exec.LIVE[0] = False` 是默认值
4. **一切可核验** —— 金额、点位、成交、盈亏都要能从交易所流水/日志复核
5. **保命机制先挂后撤** —— 改止损必须"先挂新 → 确认成功 → 才撤旧"
6. **订单开之前必须经用户审批**（09-15 新增）
