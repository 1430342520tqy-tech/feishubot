### 0.1 B2 外部巡检（已实现并部署，**不依赖机器人进程、不重启机器人**）

**为什么不照原文档的方案做**：原方案是「每 5 分钟跑 health_check.py，输出含
`BrowserContext` 就告警」。实测**这样会永久告警**：health_check 扫的是 run.log 的
**最近 400 行**，而实测最近 2000 行里有 **694 条** `BrowserContext` / `页面不存在` /
`重开失败`（全是 16:07–17:40 那场事故的历史行）。旧行会一直赖在窗口里 →
每轮都命中 → 几天内就被无视 = 告警疲劳。

**实际实现**：`tools/log_watch.py` —— **按字节游标只认新增行**，游标落盘；
另加 health_check 没有的两个维度：**心跳停摆**与**进程/状态文件停更**。

| 检测维度 | 判据 |
|---|---|
| 新增故障行 | 关键字表（`BrowserContext` / `重开失败` / `开页异常` / `轮询异常` / `熔断` / `对账闸门` / `结论=不一致` / `Traceback` / `重建失败` / `重建浏览器失败` / `浏览器自动重启失败`） |
| 心跳停摆 | 最后一条心跳超过 **10 分钟** → 告警 |
| 进程消失 | `/proc` 里找不到 `dryrun_bot2.py` → 告警 |
| 状态停更 | `state.json` 超过 **10 分钟**未更新 → 告警 |
| 防轰炸 | 同类告警 **30 分钟冷却** |
| 日志轮转 | 文件变小（copytruncate）→ 游标自动归零 |

**关键字是"挑出来"的，不是随手写的**（都基于实测频率）：
- **不收** `页面不存在/已关闭，正在重新打开…`：单标签页被关后重开成功是小事，
  真出事会由下一行的 `重开失败` 暴露（事故里两行成对出现）
- **不收** 泛指的 `差异`：影子模式下「纸面有仓、交易所无仓」本来就记为"差异"且属预期
  （实测启动时打 `差异 6 条 ｜ 结论=一致`）→ 只收 `结论=不一致`
- 实测 `[对账]` 只在启动/指令时打，**近 1 小时 0 条**，不会周期性刷屏

**部署物**（仓库 `deploy/`）：`signalbot-watch.service` + `signalbot-watch.timer`（每 5 分钟）
+ `install-watch.sh`（幂等安装/卸载）+ `logrotate-signal-bot`（**尚未安装，等用户确认**）

### 0.3 B1 根因**已被推翻并重新定位**（原文档写错了）

原文档判断「内核无 OOM → 更像 Chromium 自身崩溃」。**实测 journal 证明不是崩溃，是
systemd-logind 主动杀掉了整个浏览器。** 证据链：

```
16:07:23  sshd: session closed for user ubuntu        ← 最后一个登录会话登出
16:07:23  systemd-logind: Removed session 79.
16:07:33  systemd[1]: Stopping User Manager for UID 1000...      ← 整个用户管理器被停
16:07:33  systemd[5504]: Stopping app-org.chromium.Chromium-31673.scope...
16:07:36  Stopped app-org.chromium.Chromium-31673.scope.
16:07:40  run.log: 页面不存在/已关闭，正在重新打开…               ← 机器人开始瞎
17:40:31  run.log: 最后一条 BrowserContext.new_page ... closed（全程共 2488 条）
```

进程归属（决定性）：

```
Chromium      → /user.slice/user-1000.slice/user@1000.service/app.slice/app-org.chromium.<pid>.scope
机器人(pm2)    → /system.slice/pm2-ubuntu.service      ← 所以它毫发无伤、一直打「运行中」心跳
Xvfb          → /system.slice/xvfb.service
Linger = no                                            ← 关键开关
```

**机制**：`Linger=no` 时，ubuntu 的最后一个登录会话一结束，systemd 就停掉 `user@1000.service`，
**连带杀掉挂在它下面的 Chromium scope**。机器人本体在 pm2 系统服务里，于是「看起来正常、实际全瞎」
93 分钟。**这是必然复现的行为，不是偶发崩溃。**

**修复（第 1 步，已执行并验证）**：`sudo loginctl enable-linger ubuntu` → `Linger=yes`，
标记文件 `/var/lib/systemd/linger/ubuntu` 已落盘（重启后仍生效）。

**验证方法（可复现，非推测）**：主动把 logind 会话数清零（`loginctl terminate-session` 掉全部会话），
观察 journal：

```
19:03:43  Removed session 525.            ← 会话数 = 0
          ↓ 54 秒零会话窗口
19:04:37  New session 527.                ← 重连
判定：'Stopping User Manager for UID 1000' = 0 次；'chromium scope Stopping' = 0 次
结果：Chromium PID 84211 未变（存活 01:18:07）；机器人 PID 84196 未变；
      run.log 里「重开失败」计数 2488 → 2488（一条没新增）
对照 16:07 那次同样动作：10 秒内用户管理器被停 → 浏览器被杀 → 瞎 93 分钟。
```

### 0.5 本次新发现（原文档没有）

**B10 —— 英文常用词撞币种代码，把单币信号误判成「多币种总结」（已用代码 + 数据双向证实）**

`find_all_coins()` 用的是**大小写不敏感**的词边界正则：

```python
re.search(r"(?<![A-Za-z0-9])" + re.escape(s) + r"(?![A-Za-z0-9])", t, re.I)
```

而 `ONUSDT` / `ATUSDT` / `THEUSDT` 都是币安真实合约（已在 `fapi_symbols.json` 里核对），
于是句子里的 **`on` / `at` / `the`** 被当成币种。实测现场（19:03）：


**影响**：任何含 on/at/the 的英文信号都会**误判成多币种**→ 触发假的多币种审批分支，

### 0.7 🔴 B14 —— 生产实测抓到一笔「假亏损」（19:20，**同一晚新发现**）

**事故证据（全部可在 run.log / trades_dryrun.jsonl 复核）**：
```
19:19:04  暴富龙发消息，其中 ETH 段是**新信号**：做多、分批 2465/2466、止盈 2520
19:20:12  🎛 用户回复处理：开=['ETH']

19:20:38  【已结单·纸面】ETH SHORT | 全部止盈完成，累计盈亏：-5.9U
```

**根因**：ETH 持仓是 **SHORT（入场 2503.49）**，但"更新已有持仓止盈"这条路径
用的是**新信号的方向**（做多、入场 2465.5）去做方向校验 —— `2520 > 2465.5` 合法通过，
于是被**无条件**写到 SHORT 持仓上。空单的止盈落在入场价**上方** →
当前价 2503 本来就 ≤ 2520 → **瞬间被判为"止盈成交"**。

**后果（都是真数据，不是推测）**：
- `trades_dryrun.jsonl`：ETH 的 `exit_why` = **"全部止盈"**，而 `pnl` = **-5.94U**、`pnl_net` = **-6.5665U**
  —— **把一笔亏损记成了"全部止盈"**
- 风控计数被污染：`consec_loss` **0 → 1**、`day_pnl` = -6.5665
- ⚠️ `max_consec_loss: 3` —— **再来两次这种假亏损就会触发连亏熔断、自动暂停交易**
- 已核对当时其余 5 笔持仓的止盈方向都正常，没有遗留坏状态

**这是 B3 的同源问题**：`finalize_pending` 里"新开仓"那条路径过了完整校验，
"**更新已有持仓**"这条路径**完全没过**。

## 三、相关设计原则（改代码时必须遵守）

1. **绝不猜价** —— 读不准就询问用户，不自动开单
2. **绝不静默丢弃** —— 任何解析失败/未识别信号都要留日志并通知
3. **默认不碰真钱** —— `binance_exec.LIVE[0] = False` 是默认值
4. **一切可核验** —— 金额、点位、成交、盈亏都要能从交易所流水/日志复核
5. **保命机制先挂后撤** —— 改止损必须"先挂新 → 确认成功 → 才撤旧"
6. **订单开之前必须经用户审批**（09-15 新增）
