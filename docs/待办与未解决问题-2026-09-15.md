|---|---|---|

- **实测结论（不含糊）**：这只堵住"整图标签全丢"这一类，**数值错位仍在**——
  同一张 `7685512041913666779_0.png` 三次跑出三组不同止盈。

### 0.16.10 C2 定案：关键标签「两次独立读数 + 单调性校验」

**先说为什么否掉 ③+④ 的轴拟合**（两版都试过，都有实测数据，都不成立）：

| 版本 | 做法 | 实测结果 |
|---|---|---|
| v1 | 用全部标签的 (y, 价格) 拟合价格轴，再用轴值纠正/补齐 | 把正确的 7.180/8.216/9.289 改成 7.263/8.216/9.230 |
| v2 | 只用长线的**覆盖行 y** 做拟合（"线 y"与"文字 y"分开） | UNI 图把正确红线 6.396 判成"可疑"要改成 6.486；另一张拟合中位残差 12.7%（输入点被错值污染，循环污染） |

**根因**：拟合的输入本身就是那批可能错位的 OCR 值（循环污染）；且合并区域的 y 误差 0.5%~5%，
与被纠正的误差同一量级 → 只能"更自信地错"。故两版都撤回，不留半成品。

**最终方案（已实现）**：对**关键标签**（红色止损线 + 够长的止盈候选线，≤6 个）做两次**互相独立**的读数：

| 读数 | 实现 |
|---|---|

### B1 —— 浏览器上下文死亡后无法自愈（最高优先级）

**真实事故证据**
```

16:07:40  页面不存在/已关闭，正在重新打开…
16:07:51  页面不存在/已关闭，正在重新打开…   ← 每 3 秒重试，一直失败
17:19:17  重开失败：BrowserContext.new_page: Target page, context or browser has been closed
   ⋯ 心跳一直打「运行中 | 持仓 6 笔」       ← 看起来正常，实际完全读不到任何群
17:40:15  重启机器人 → 恢复
```

**后果**：机器人"瞎"了 **93 分钟**，期间四个群的消息**全部漏掉**；
用户 16:37 发的「只开btc和doge」、17:10 发的「持仓情况」「帮助」**根本没被读到** →
用户感知为"机器人指令没反应"。

**根因**：~~整个 `BrowserContext` 死亡。上一轮加的"页面重开失败继续重试"
**只覆盖标签页被关，覆盖不了上下文整体死亡** —— `ctx.new_page()` 必然失败。~~

> ⚠️ **本节根因已于 2026-09-15 晚修正，见上面第 0.1 节**：
> 不是 Chromium 崩溃，是 **systemd-logind 因 `Linger=no` 停掉 `user@1000` 时把 Chromium 连坐杀掉**。
> 触发器已用 `loginctl enable-linger ubuntu` 消除并验证；自愈代码见第 0.2 节。

**修法**：检测到 `Target page, context or browser has been closed`
→ **主动重启整个浏览器**（重新 `launch_persistent_context` + 重开所有页面 + 重新预热），并**立即告警**。
（已实现，见第 0.2 节，`--selftest-b1` 全通过，**待生产重启验证**）

**旁证**：~~内核日志**无 OOM 记录**，不是内存问题，更像 Chromium 自身崩溃。~~
→ **已修正**：确实无 OOM（本次用 `sudo dmesg`/`journalctl` 复核确认），但也不是 Chromium 崩溃，

### B2 —— 失联看门狗阈值太长 + 检测维度不够

- 现状 `silence_alert_hours: 6` → **6 小时才报警，救不了 B1 这种 93 分钟的事故**

> 实测能把 `BrowserContext.new_page: ... has been closed` 原样列出（32 条）。

## 三、相关设计原则（改代码时必须遵守）

1. **绝不猜价** —— 读不准就询问用户，不自动开单
2. **绝不静默丢弃** —— 任何解析失败/未识别信号都要留日志并通知
3. **默认不碰真钱** —— `binance_exec.LIVE[0] = False` 是默认值
4. **一切可核验** —— 金额、点位、成交、盈亏都要能从交易所流水/日志复核
5. **保命机制先挂后撤** —— 改止损必须"先挂新 → 确认成功 → 才撤旧"
6. **订单开之前必须经用户审批**（09-15 新增）
