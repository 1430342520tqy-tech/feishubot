## 一、开单规则全集（当前生效）

### 1.1 资金与规模

| 项 | 值 | 怎么改 |
|---|---|---|
| 单笔保证金 | **300 USDT** | `修改金额 300` |
| 杠杆 | **3 倍** | `修改杠杆 3` |
| 单笔名义 | **900 USDT**（=保证金×杠杆） | 随上面两项自动变 |
| 持仓上限 | 代码默认 **5**，当前配置 **7** | `修改持仓上限 6`（范围 1~50） |
| 止盈档位 | **3 档**（第 4 档起**截断无视**，`TP_TIERS=3`） | 代码常量 |
| 轮询间隔 | **0.5 秒**（`POLL_SEC`） | 代码常量 |
| 待合并窗口 | **4 秒**（`PENDING_WAIT`；信息齐全时可提前到 1.5 秒出单） | 代码常量 |
| 手续费 | 挂单(maker) **万2**、吃单(taker) **万5**，计入每笔盈亏 | 代码常量 |
| 待确认超时 | **30 分钟**没回复自动作废 | 代码常量 |

### 1.2 入场价规则（默认，除「黄金mansoor」外的群）

比较「博主给的点位」与「当前币安市价」：

| 情形 | 动作 |
|---|---|
| 差值 ≤ **2%** | **市价、一次满仓 900U** |
| 做多 且 市价高于博主价 **>2%** | **不追高**：`博主价×1.01` 挂 150U + `博主价` 挂 150U（**两笔限价**） |
| 做空 且 市价低于博主价 **>2%** | **不追空**：`博主价×0.99` 挂 150U + `博主价` 挂 150U（**两笔限价**） |
| 做多 且 市价**低于**博主价 / 做空 且 市价**高于**博主价 | **直接市价**（对我们有利），止损不变 |

### 1.3 「黄金mansoor」专属规则（只对这一组生效）

配置：`runtime_config.json` 的 `strict_limit_groups: ["黄金mansoor"]`

- 做多：市价 ≤ 博主价 → **市价进**；市价 > 博主价 → **按博主价挂限价**等他回踩
- 做空：反之
- 一句话：**只在市价对我们更有利时市价进，否则一律按博主价挂限价**

### 1.4 分批建仓（适用所有博主）

博主给了 **≥2 个入场点位** → **保证金等分**，每个点位挂一笔限价（2 个点各 50%、3 个点各 1/3）。
识别写法：「76666 75555继续分批接多」「跌到95第一笔，90第二笔」。
⚠️ 同时出现「头仓/首仓/底仓/试仓」+ 分批 → 分几笔不确定 → **转人工审批**。

### 1.5 止损怎么推导（按顺序，命中即止）

| 顺序 | 情形 | 规则 |
|---|---|---|
| 1 | 博主给了止损 | 直接用（**区间一律取中间值**） |
| 2 | 没给止损、给了百分比（如「带个3%止损」） | 按开仓价折算：做多 = 入场×(1−3%) |
| 3 | 没给止损、给了止盈 | **止损 = 入场 ∓ 第一止盈距离的一半**（保证 2:1） |
| 4 | 止损和止盈都没读到 | **只发通知，绝不下单**（绝对底线） |

### 1.6 止盈怎么推导

- 博主给的档位 → **按「离入场价由近到远」排序**（⚠️ 不是按数值大小），**最多取 3 档**
- 博主**只给止损、没给止盈** → 按 **2R 反推**（盈亏比 2:1），**到价全平**
- 博主**后补**真实止盈位 → 撤掉 2R 兜底那档，按真实档位重挂

### 1.7 五道机器校验（任一条不过都**不会自动开单**）

| # | 校验 | 不过怎么办 |
|---|---|---|
| 1 | **止损方向**：多单止损必须在下、空单必须在上 | **直接拒绝**并通知你 |
| 2 | **止盈方向**：方向不对的档位剔除 | 剔除该档；全被剔则用 2R 兜底 |
| 3 | **开仓价合理性**：与市价偏离 > **20%** | **转人工审批** |
| 4 | **止损距离合理性**：距入场 > **40%** 或 < **0.05%** | **转人工审批** |
| 5 | **止盈是否已被越过**：止盈位已被当前市价穿越 | **转人工审批**（信号过期或张冠李戴） |
| 6 | 一条消息里出现 **≥2 个币种**（笼统总结） | **转人工审批** |
| 7 | 总敞口将超上限 | **不开**，只通知 |

### 1.8 审批闸门（2026-09-15 新增，你的第 12 条要求）

- `REQUIRE_APPROVAL` **默认开启**（可用 `runtime_config.json` 的 `require_approval` 关）
- **所有新开仓在开之前都会先问你**，回「开」才开、回「不开」作废
- 达到持仓上限时**与审批合并成一次询问**（不会问你两遍）
- 审批通知里带全：**币种 / 方向 / 来源群 / 时间 / 入场 / 保证金 / 杠杆 / 名义 /
  止损位 / 止损点数（不含杠杆）/ 打止损亏多少 / 各档止盈 / 各档预期收益率（含杠杆）/ 盈亏比**
- 已有持仓的**止盈/止损更新不算开新单**，不进这道闸门
- 待你确认的信号**落盘保存**，机器人意外重启也不会丢

### 1.9 风控与熔断

| 机制 | 阈值 | 触发后 |
|---|---|---|
| 连亏熔断 | **连续 3 笔**亏损 | 暂停开单 + 告警（仍监控、已持仓继续管理），发「继续」恢复 |
| 当日亏损熔断 | 当日已实现净亏 **300U** | 同上 |
| 总敞口上限 | `max_total_margin`（0 = 持仓上限×保证金） | 新单不开，只通知 |
| **启动对账闸门** | state.json 与币安真实持仓不一致 | **阻止真实开仓**（仍监控），发「重新对账」清除 |
| 失联看门狗 | **6 小时**没抓到任何新消息 | 告警（可配 `silence_alert_hours`） |
| 回补闸门 | 停机期间积压、且发出时间 > **30 分钟** | **只通报不下单**；单次最多真正处理 50 条 |

### 1.10 持仓管理与结算

- **止损优先**：先判止损，再看止盈（同一轮里止损条件成立就先平）
- 止损成交 → **全平**，费用按 **taker 万5**，结单原因记为「止损」或「保本止损(TP1后)」
- **逐档止盈**：每档平 **1/档数**（3 档 → 各 33.3%），费用按 **maker 万2**
  - 2R 兜底档特殊：**一次全平**（`tp_part = 1.0`）
- **TP1 成交后，止损自动移到开仓价**（保本损）
- 全部平完 → 结单，写 `trades_dryrun.jsonl`（含结单时间/持仓时长/净盈亏）
- 已有持仓又收到同币信号 → **不重复开单**，只提示现有仓位；
  若该仓是 2R 兜底且本次有真实止盈 → 替换止盈档
  （⚠️ 替换前**按持仓自己的方向与入场价**校验，不允许把止盈挂到反方向 —— B14 修复）
- 博主发「止盈达成」这类**只是通报** → 只回报你自己的持仓情况，**绝不动仓位**
- 🆕 **结单/止损通报 → 直接忽略、不推送**（用户 2026-09-16 要求）：
  「Trade Closed — EIGEN/USDT LONG … Stop loss hit」这类"博主说一声"的消息**不是开单信号**。
  现在在**多币种拆分之前**就挡掉：含止损/平仓字样 → **完全不推送、不动仓位**；
  只含「止盈达成」→ 仍按用户第 9 条要求回报**你自己的持仓**。
  （原来这一挡排在管理指令之后，于是上述止损通报被 AI 读成 `close_all`、连推 3 条【博主指令】——顺序反了）
- 🆕 **管理指令术语一律中文**：`close_all` → **全部平仓**、`trim` → **减仓**、
  `move_stop_to_cost` → **止损移到开仓价**
- 🆕 **审批消息（【信号·待你确认】）里也带耗时行**（用户 2026-09-16 要求）：
  `⏱ 从信号发出到推送 共 18.4s（发现 9.0s / 抓图 0.0s / 解析 0.8s / 读图 0.0s / 等齐后续消息 8.6s）`
  —— 分段与出单通知里的 ⏱ 行**完全一致**

### 1.11 真实下单层（影子 / 实盘）

**影子模式（当前）**：只生成"将会向币安发什么单"的计划，落 `v21/real_orders.jsonl`，**一条委托都不发**。

**实盘模式**（`live_trading: true`，需 `进入实盘模式 确认`）：
- 入场：市价单 或 分批限价腿（各腿名义 = 900 ÷ 腿数）
- 止盈：每档一张 **LIMIT 限价单**（maker）
- 止损：**必须走 STOP_MARKET**（限价单会立即成交）。
  走**币安 Algo 接口** `POST /fapi/v1/algoOrder`（`algoType=CONDITIONAL`），
  参数名是 **`triggerPrice`**（不是经典接口的 `stopPrice`）
- 双向持仓（hedge）下**不传 `reduceOnly`**（会被拒 -1106），用 `positionSide` 表达
- 改止损：**先挂新止损 → 确认成功 → 才撤旧**（防裸奔）
- 每个仓位开仓时打 `real_layer = 纸面/实盘` 标记 → **切换模式不影响已有持仓**
- 🆕 **手工仓护栏（用户 2026-09-16 明确要求：机器人在交易所有手工仓时不得有任何干涉）**：
  启动对账时把「交易所有仓、纸面无记录」的币登记为 **`MANUAL_COINS` 手工仓**（落盘 `state.json` 的 `manual`），
  之后对这些币：**不开新仓、不平仓/减仓、不改止损，也不把交易所持仓数量拿来挂保护**
  （否则机器人的止损会覆盖到用户手工仓的数量 = 干涉）。触发时**硬拦 + 飞书告警**。
  手工仓平掉后发「解除手工仓 X」清除。
  `_real_qty_or_estimate()` 对这类币**只用纸面估算**，绝不用交易所数量。
  - ⚠️ **已知边界（2026-09-18 实测踩到）**：护栏的判据是「交易所有仓 **且** 纸面无记录」，
    所以**同一个币既在纸面账里、又是你的手工仓时，护栏认不出来**。
    实例：`LAB` —— 交易所真实持仓 `11700` 张（≈576U，你的手工仓），
    机器人纸面账里同时有一条 `LAB` 纸面单（`292` 张，来自 13:15 的博主信号，`mode=shadow`，从没真下单）。
    此时对账只会报「数量级差异 1 条」，**影子模式无害，但一开实盘机器人就会把它当成自己的仓**，
    去挂真实止损 0.04857（卖 291 张）+ 三层止盈 → 直接动到你的仓。
    处置（2026-09-18 已执行）：把 `LAB` 手工写进 `state.json` 的 `manual`、并删掉纸面那条 `LAB` 记录。
    **实盘前的固定动作**：核对「交易所数量 vs 纸面估算」的数量级差异，凡有差异的币先确认归属，宁可先挂护栏。
- 🆕 **归属待确认（用户 2026-09-18 明确要求：这种情况机器人要自己拦住，不许猜）**：
  - **触发条件**：**启动对账**时出现「同一个币 **交易所有仓** **且** 机器人**纸面也有该币的记录**，
    但两边数量差**超过容差（默认 5%）**」→ 该币进 `AMBIG_COINS`（**归属待确认**），
    落盘 `state.json` 的 `ambig`，并**主动发飞书问用户**：
    ```
    ❓【归属待确认】LAB：交易所有 11700 张、机器人纸面只记了 292 张。这币到底是谁的？
    · 是你的手工仓 → 回「LAB 是我的手工仓」
    · 是机器人自己开的 → 回「LAB 是机器人的仓」
    在你回话之前，机器人不会对 LAB 发任何真单（不开新仓、不平仓/减仓、不改止损），
    也不会拿交易所的持仓数量去挂保护。
    ```
  - **回话之前：一律不发真单**。拦截强度与上面的手工仓护栏**完全一致**：
    不开新仓、不平仓/减仓、不改止损（TP 后的止损同步、了结后的撤单都跳过）、
    看门狗也**不替它补挂止损**，`_real_qty_or_estimate()` 对它**只用纸面估算、绝不用交易所数量**。
    实盘模式下它同时**计入启动对账闸门**（`RECONCILE["blocked"]=True`），
    **影子模式下只记录、不阻断**（沿用原有语义）。
  - **回话指令**：`LAB 是我的手工仓`（→ 进手工仓护栏，此后按 `MANUAL_COINS` 保护）
    或 `LAB 是机器人的仓` / `LAB 不是手工仓`（→ 只解除待确认；⚠️ 纸面数量与交易所**仍然不一致**，
    机器人只记录、**不会自动改账**，请自己核对）。
  - 交易所已经没有这个币时**自动移出**待确认名单（按交易所实时持仓核对；**读不到持仓就不删**）。
  - ⚠️ 与手工仓的关键区别：归属待确认的币**纸面有记录**，所以它**会**出现在 `open_pos` 里 ——
    凡是"靠手工仓进不了 `open_pos`"来保证不碰用户仓位的地方（TP 后同步止损、了结后撤单、看门狗补挂），
    AMBIG 都必须**单独再挡一次**。
  - 自检：`--selftest-ledger` 里的 `[8m-⑥] 手工仓/归属待确认闸门`。
- 🆕 **本次同时修的既有缺陷（必须知道）**：`ledger.reconcile` 对**已登记的手工仓**照样生成 `only_real` 差异
  → `startup_reconcile` 的 `consistent` 永远为 False → 实盘下 `RECONCILE["blocked"]` 恒为 True
  → **用户只要持有任何手工仓，实盘就永远开不出新仓**。
  现在改为：把差异分成「**本次运行开始时就已经登记**的手工仓（不计入闸门）」与「未解决（计入闸门）」两类，
  差异明细（`RECONCILE["diffs"]`）**照样全部保留**供日志与「重新对账」指令查询。

### 🆕 第二轮（2026-09-18 独立审查后修的 6 处硬伤，用户要求逐条修掉）

审查方式：AST 抽出真实函数源码 + 打桩执行（结论已实测复现）。逐条：

1. **实盘闸门被改宽（最危险）**：第一轮的实现是"**先**登记手工仓、**再**按是否在 `MANUAL_COINS` 里拆分差异"，
   于是拆分那一刻"已登记"**恒为真** → **所有** `only_real` 全被排除 → `state.json` 整个丢失
   （交易所有 3 仓、纸面全空）也 `blocked=False` 并照开真单（防双倍敞口的闸门被永久废掉）。
   现在只在 `startup_reconcile` **进入时快照** `_manual_known = set(MANUAL_COINS)`（= 从 `state.json` 恢复出来的那份），
   只有那份名单里的币才豁免闸门；**本次新发现**的孤儿仓照样登记为手工仓（护栏不变），
   **但计入闸门**并单独告警：「本次新发现 N 个交易所有仓、纸面无记录的币…回「X 是我的手工仓」或发「重新对账」解除」。
2. **`watch_entries()` 完全没有守卫**：限价入场成交后照样 `after_entry_filled`（真挂三层止盈+Algo 止损）、
   超时照样 `cancel_all`（撤掉该币**所有**挂单，含你手工仓的止损单 = 手工仓变裸仓）。
   现在**循环第一件事**就过 `no_touch_guard`，命中即丢弃该条目 + 告警（**一个真实动作都不发**）。
3. **MANUAL 与 AMBIG 在维护路径上同等受保护**：第一轮只给 AMBIG 补了 4 处，且注释断言
   「手工仓进不了 `open_pos`（`real_plan_open` 已拦）」——**这个前提是错的**（`open_pos[coin]=tr` 建在
   `real_plan_open` 之前，`real_layer=_be_mode()` 只看 LIVE 开关）。实测 `MANUAL={'LAB'}` 时
   `watch_naked()` 会执行 `place_sl_stop_market('LABUSDT','LONG',0.04, 18000.0)`（交易所只有 11700 张）。
   现在：① **根因**——建/更新纸面仓时命中 no_touch 就把 `real_layer` **强制标成"影子"**
   （`_mark_real_layer()`，实盘下这些币的真实开仓本来就被拦掉，所以"影子"是如实的）；
   ② **双保险**——那 4 处统一换成 `no_touch_block`（手工仓 + AMBIG 同时生效）。
   取舍原则（写进代码）：**绝不碰用户仓位优先于一切**；机器人**自己**的真仓不属于 no_touch 币，
   `real_layer` 照旧"实盘"，看门狗补挂能力不受影响（不能让自己真仓失去止损 = 裸奔）。
4. **「X 是机器人的仓」要落"已答复"记录**：原来只做内存 `discard`，每次启动对账只要还有数量不符就重新
   `add` → **用户以为解除了，重启后又进 AMBIG、又问、又拦真单**。
   现在 `state.json` 增加 `"ambig_ack": [...]`（与 `"ambig"` 平行，落盘/恢复齐全）；
   答复后记入 ack → 该币不再进 AMBIG，若仍数量不符则**只发数量不符告警、不计入闸门、不再问**。
   「X 是我的手工仓」进 `MANUAL_COINS` 即**等效已答复**（`_ambig_acked()` 两者都认）。
5. **影子模式 `RECONCILE["ok"]` 语义还原**：`ok` = 「**有没有差异**」（有差异即 False），
   闸门单独看 `RECONCILE["blocked"]`，并新增 `manual_diffs` / `acked_diffs` / `pending` 三个字段。
   「状态」与「重新对账」据此区分三种情况：①无差异 ②有差异但都不计入闸门（你的手工仓 / 已答复的归属确认）
   ③存在未解决差异（实盘会被拦，并列出是哪几条；影子模式注明"只记录、不拦真单"）。
   ⚠️ 副作用（有意为之）：影子模式下"纸面有仓、交易所没有"也会如实显示为"有差异"——
   这正是 LAB 事故被掩盖的原因，用户要求影子模式下也必须能看见差异。
6. **`_ambig_prune` / `_manual_prune` 的空集合防护**：`ledger.real_ledger` 对脏行是**静默 continue**，
   所以"读到空集合"**不等于**"交易所有没有仓"；旧代码在 `rsyms` 为空时清空名单并落盘 = **静默解除闸门**。
   现在：读到空集合而名单非空 → **保留名单 + 告警**（写明"这次没读到任何持仓，为避免误解除，名单原样保留"）。
7. **归属答复的识别能力**：币种解析改走 `_resolve_coin_strict()`（复用 `resolve_coin` 的**清单校验** +
   中文别名表），支持 `$BTC 是我的手工仓` / `比特币 是我的手工仓`；
   `HELLO 是机器人的仓` 这种**不是币种**的写法不再被当指令（旧实现只看 `resolve_coin` 的第一个返回值）。
   底线不变：整句匹配 + 长度门槛，**认不出就回一句闲聊提示**，绝不瞎猜、绝不放行。

## 二、解析是怎么做的（完整链路）

### 2.1 抓取

🆕 **两种取消息方式（`runtime_config.json` 的 `fetch_mode`，热加载，改完即生效）**：

| 模式 | 说明 |
|---|---|
| **`api`（当前默认）** | **飞书官方 API + 用户身份令牌**（`src/feishu_api.py`）。以**用户本人**身份读你自己的群 —— 机器人**不需要被拉进群**、**不需要浏览器**。实测图片是**原图**（与网页抓下来的字节完全相同）、延迟从 5~30 秒降到 1~2 秒、**重启没有 4.5 分钟盲窗** |
| `browser` | 老方式：爬飞书网页（Chromium + 每群一个标签页）。**完整保留**，API 出问题时可一键切回兜底 |

**API 模式的关键细节**：
- 令牌：`authorization_code` → `user_access_token`（2 小时）+ `refresh_token`（**7 天，自动续期**），
  文件 `feishu_user_token.json`（**600 权限、不进 Git**）；刷新失败会**告警**提醒重新授权
- 拿到的消息类型：`text`（机器人自己的通知）、`interactive`（**博主发的卡片** —— 用递归抽取
  把所有 `text`/`img` 节点按顺序抠出来）、`image`（纯图）
- 图片：卡片里的 `{"tag":"img","image_key":…}` → 用
  `GET /im/v1/messages/{message_id}/resources/{image_key}?type=image` 下**原图**
  （⚠️ `/im/v1/images/{key}` 会报 14049，那个接口只认应用自己上传的图）
- 行结构：`feishu_api.fetch_new()` 产出与网页版 `SCAN_JS` **完全相同**的字段
  （`id/t_sig/text/nimg/loaded/nblob/_imgs`）→ **下游解析/审批/下单逻辑一行不改**
- 游标：按 `create_time`(毫秒) 存 `state.json` 的 `last_api`；去重仍用 `SEEN`
  （⚠️ API 的 id 与网页版 id 不同源，**不互相污染**）
- 自检：`--selftest-feishu`（卡片抽取夹具 + 消息 id 稳定性 + 行结构 + 线上只读自检）；「状态」指令会显示取消息方式与令牌剩余时间

**浏览器模式（兜底）的老逻辑**：

1. 4 个监控群**各占一个独立标签页**，打开后一直停在该群（避免读错群），并做标题校验
2. 每轮先读一次**左侧会话列表预览**（一次 JS 调用 ≈0.2s）判断哪个群有新消息
3. 兜底：每 30 轮**全量扫所有群**；列表里看不到的群每 3 轮轮换扫 1 个
4. 按 `message-id` 去重（`SEEN`，防重复开单），游标逐条推进（进程中途挂掉不会丢单）

### 2.2 消息门槛（不满足就跳过）

- **过滤自己的通知**：文案含 `【跟单机器人】/【博主指令】/【信号·…` 等 → 跳过（防自我循环）
- 指令优先：在「开单记录」「机器人开单通知」群里**先试指令**，命中就不再当信号
- 信号关键词（`long/short/做多/做空/止损/止盈/TP/SL/CMP…`）**或**消息里带图 → 才算候选
- 🆕 **带图的判定已放宽（B16）**：只要消息里有图元素（`nimg>0`）就算"带图"，
  **不再要求"图已经加载完"**（原来 `loaded>0 or nimg>=2`）。
  21:57 那条 UNI 图消息就是死在旧判据上：单张图未加载完 → `nimg=1/loaded=0`
  → 被判「闲聊/无关，跳过」，**连抓图都不会尝试**。
  抓图等待预算：`img_wait_ms()` —— 内容图/未加载的单图/无关键词的消息给 6 秒
  （JS 一拿到可用图就提前返回，不真等满），其余 1.2 秒。实测纯文本消息 `nimg=0`，不会被拖进抓图。
- 都不满足 → 记一行「闲聊/无关，跳过」

### 2.3 三层解析（**能用便宜的就不用贵的**）

**第一层：本地正则 `fast_parse`（0 次 AI 调用）**
能识别：英文/中文方向词、币种（别名表 + 722 个币安 USDT-M 合约清单）、
止损（`close under` / `SL` / `stop loss` / `止损`）、加仓（`DCA/加仓`）、入场（`Entry/入场/现价/CMP/@/77065价格做空`）、
**止盈（逐个关键词分段扫描，每段取到下一个关键词为止，不会漏档也不会把止损数字当止盈）**、
区间入场（取中间值）、**分批建仓**、**百分比止损**、**止损区间**、**止盈区间**。

**第二层：可疑检测 `fast_parse_suspect` → 需要时叫 AI `parse_text`**
触发条件：① 止盈关键词数量 > 读到的档数（说明少读了）② 没读到止损。
> 存在的意义：快速解析命中会跳过 AI，一旦少读就是**静默丢数据**
> （09-13 实测：「第一止盈74500 第二止盈70500」被读成只有 74500）。

AI 用 `deepseek-v4-flash`、`temperature=0`，只输出 JSON；prompt 里 8 条硬规则：
① 只用消息里真实出现的数字，**绝不编造** ② 止盈写在图上则标记 `tp_on_chart` 且 targets 留空
③ 开仓区间 → `entryRange` ④ 分批点位 → `entryLegs` ⑤ 止损区间 → `stopRange`
⑥ 百分比止损 → `stopPct` ⑦ 止盈区间 → `targetRanges` ⑧ 方向必须按原文判断。

**第三层：读图 `read_chart`（视觉）**
只在「文字/卡片不够」时调用（需要止损，或止盈不足 3 档），**与 AI 解析并行跑**（线程），
且**同一张图有缓存**（不重复调 AI）。

**读图算法（不是让 AI 看图，而是本地像素分析 + OCR）**：
1. 只扫图片**右侧 76%~98.5%** 宽度的价格轴区域（K 线图右侧标签栏）
2. 按颜色把长横线（≥35 像素）分类，合并成标签
3. **红色 = 止损**：取**最低**那个红色标签
4. 红色**上方最近**的标签 = **入场价**（⚠️ 文本写 CMP/现价时以**当前市价**为准，见 2.5 的 C1）
5. 其余在入场上方、覆盖宽度 ≥ `TP_MIN_COV` 的标签 = **止盈位**（最多 3 档）
6. 🆕 `TP_MIN_COV = 0.55`（原来是 0.85，实测会把真实止盈线判掉）
7. 🆕 候选多于 3 档时：**先按横线长度取最长的三条**，再按价格由近到远排序

> 🆕 **为什么改覆盖率门槛（2026-09-16 实测）**：真实 UNI 图
> （`v21/imgs/7685715944936623383_0.png`）上三条止盈横线的实测覆盖率是
> **0.743 / 0.787 / 0.863** —— 横线会被 K 线遮住，天然低于 100%，旧门槛 0.85 把
> **7.180 与 8.216 两档直接判掉**，只读出 9.289（TP1/TP2 静默丢失）。
> 同图上入场线/止损线是短线（实测覆盖率 0.195~0.2），所以 0.55 仍能过滤它们。
> 改后同一张图读出 **7.180 / 8.216 / 9.289**。

🆕 **标签读数交叉校验（2026-09-16，用户选定方案）—— 解决「读数乱跳」**

背景：批量 OCR 是"把 N 个标签拼成一张图 + 左侧黄色序号"，让模型返回 `{"1":v,…}`，
再用 `nums.get(str(i))` 贴回第 i 个标签。**模型一漏答/错位，"序号↔数值"就配错，甚至整图标签全丢**：
实测同一份代码、同一张图跑两遍，59 张真实图里 **9 张读数不同**
（例：`7685319584487951562_0.png` 第一次 `sl=0.0 / entry=0.04 / tps=[88.0]`，
第二次直接「无红色止损标签」）。

现在对**关键标签**（红色止损线 + 够长的止盈候选线，≤6 个）做**两次互相独立的读数**：

| 读数 | 来源 |
|---|---|
| 第 1 次 | 批量拼图 OCR（已有） |
| 第 2 次 | `_ocr_one_label()` —— **单个标签单独裁图、单独一次调用**，没有"序号→数值"这一步，从机制上不可能错位 |

- 两次**一致**（相对差 ≤ 0.5%）→ 采信，并给该标签打 `verified`
- **不一致** → 标「未读到」+ 告警日志，**绝不取其中一个**（`two_read_ok()`）
- 只有一边读出来 → 采信那一边（不因一边失败而丢标签）
- 再加一道 `drop_nonmonotonic()`：同一张图上**价格必须随 y 增大而下降**（价格轴的几何性质），
  违反的一对里剔除**覆盖率更低**的那个（长线才是 KOL 真画的线）

代价：每个关键标签多一次小调用（≤6 次/图，只在需要读图时发生，同图有缓存）。
日志会打：`关键标签复核 N 个（两次一致 X / 仅单标签 Y / 仅批量 Z / 判为未读到 W）`。

🆕 **几何读图（2026-09-16，用户要求「图明明很清楚为什么读不出」）**

在像素规则之前先做一层**几何判定**：认得出"工具色框"就按框的语义定角色。

| 角色 | 几何判据 | 数字来源 |
|---|---|---|
| 方向 | 绿框在红框**上方** → 做多；绿框在下方 → 做空 | — |
| 止损 | **红框的远端边**（做多=红框下边，做空=红框上边） | 优先取"与该边几何值最接近的标签"，轴换算交叉校验 |
| 开仓 | **红框与绿框的交界边** | 文本写 CMP/现价 → 仍按规则取当前市价 |
| 止盈3（最终目标） | **绿框的远端边**（做多=上边，做空=下边） | 同上；**这一档必定保留**，不会被"按距离取前 3"挤掉 |
| 止盈1/2 | **绿框内的长横线**（覆盖率 ≥ `TP_MIN_COV`） | 它们自己的标签 |

- 认色框 `find_fill_boxes()`：工具填充是**暗色**（绿 ≈ (27,77,40)、红 ≈ (96,36,38)），
  旧 `_cls` 要 `g>110`/`r>150` 才算绿/红 → 对填充一律 None（**等于看不见框**）。
  现在按"非背景 + 亮度 ≤160 + 偏绿/偏红"认，并用亮度把填充与 EMA 曲线/蜡烛分开。
- 价格轴 `fit_axis_scale()`：用"长横线 + 它的标签值"线性拟合（带离群剔除）；坐标必须用
  **线自己的行 y**（`_line_y()`）—— 用"合并区域中心"会被线上方的标签文字拽偏 0.5%~5%
  （实测这一条就能让止损从 6.396 变成 6.513）。
- **认不出框 / 框边价格读不准 → 自动退回标签规则**（不会比原来更差）。

### 2.4 合并与多币种

- **4 秒合并窗口**（`PENDING_WAIT`，**未改动**）：同一条信号的文案/卡片/K线图可能分 1~3 条消息到达，按币合并后一起判
- 🆕 **原始消息暂存区 `RAWQ`（按「群 + 时间窗」，B16 新增）**：
  图片消息常常是**独立一条、没有文字也没有币种**，挂不进按币种索引的 `PENDING[coin]`
  （实测：20:21-20:22 黄金mansoor 两条、**23:57 UA-nurseneil2 一条** —— 图都抓到并落盘了，

  文字消息带来币种时 `rawq_bind()` **回填关联**（把图上的止损/止盈并进这条信号）；
  反向顺序（文字先到、图后到）由 `rawq_attach_pending()` 并入那条还没结束的信号。
- 🆕 **4 秒内没关联上 → 分别推送**（用户要求）：`rawq_sweep()` 推一条
  **【信号·只识别到图】**，只写图上真实读到的（币种/方向/止损/止盈，逐项标 `来源：chart`），
  **缺失的一律写「未读到（绝不猜）」，不建可审批单、不下单**。
  保护：图上币种与文字币种不一致 → 只留图，**不用图上的线覆盖文字点位**。
- 🆕 **文字有价位但没认出币种**的也不再静默丢弃：推一条
  **【信号·未能识别】**（带解析到的字段与原文，群级 10 分钟节流）。
- **多币种消息**：按句拆分（`。；;！!？?\n`），每句取**第一个**币种，各自解析后
  各自挂起等你确认，并给出一条**完整组合**清单（n 个币 = 2ⁿ−1 种非空组合）
- 时间基准：`message-id` 高位就是 Unix 秒（与页面显示一致，不靠系统时间猜）

| 指令 | 作用 |
|---|---|
| `开` / `不开` | 单条信号 |

| `只开 CL，不开 SOL` | 开 CL、作废 SOL |

| 🆕 `解除手工仓 LSK`（或 `手工仓已平 LSK`） | 你在币安自己开的仓平掉后，解除「手工仓护栏」。不写币种 = 解除全部 |
| 🆕 `<币> 是我的手工仓`（也认 `手工仓 <币>` / `$BTC 是我的手工仓` / `比特币 是我的手工仓`） | 回答机器人「这币到底是谁的？」→ 认下是**你的手工仓**，此后按手工仓护栏保护、机器人不对它发任何真单。⚠️ 第二轮起：**牌子上写错币名的写法（如 `HELLO 是我的手工仓`）不再被当指令**，机器人会回一句"没看懂" |

> 多币种审批会列出**全部非空组合**：n 个币 = 2ⁿ−1 种。
> 3 个币 → 单币 3 种 + 两两 3 种 + 「全部开」= 7 种非空组合（另加「全部不开」）。
> n≥4 时列表会退化（逐个单选 + 全部开 + 提示可自由回复），避免刷屏。
